## Introduction

To add a skill, create a directory under `laraclaw/skills/` with a `SKILL.md` file inside. There is no registration step, no command to run, and no cache to clear.

## Creating a Skill

Pick a short, lowercase, hyphenated name for the skill. That becomes both the directory name and the value in the file's frontmatter:

```bash
mkdir -p laraclaw/skills/release-notes
touch laraclaw/skills/release-notes/SKILL.md
```

## Frontmatter Requirements

Both `name` and `description` are required:

```markdown
---
name: release-notes
description: Generate user-facing release notes from a list of git commits.
---
```

The `name` should match the directory name. The registry uses the frontmatter value, but matching the directory keeps things sane. Write the `description` as an answer to *"when should I use this?"*.

## Writing Effective Skill Bodies

The body is the prompt the agent follows when the skill runs:

- **Be specific about the output format.** *"Three bullet points"* beats *"a few"*. If you want Markdown headings, say so.
- **Show, don't just tell.** If your release notes have a particular structure, include a short example. Examples are worth more than rules.
- **Constrain length.** *"Keep each section under 100 words"* beats *"Be concise"*.
- **Name the audience.** *"Written for end users, not engineers"* shapes the tone the agent picks.

A complete release-notes skill:

```markdown
---
name: release-notes
description: Generate user-facing release notes from a list of git commits.
---

You are writing release notes for the end users of a SaaS product. Take the
provided list of commits and produce notes following this structure:

## What's New
- Two to four bullet points covering user-visible features.

## Improvements
- Smaller enhancements, in 1-2 bullet points each.

## Bug Fixes
- A short list of fixes, each one sentence.

Rules:
- Skip purely internal commits (refactors, dependency updates, CI changes).
- Write in present tense ("Adds", "Fixes", "Improves").
- Don't mention commit hashes, ticket numbers, or branch names.
- If a section has no items, omit it entirely.
```

## Testing a Skill

The fastest way to test a new skill is the [terminal connector](/connectors/terminal):

```bash
php artisan laraclaw:chat
```

Then ask:

> Use the release-notes skill on these commits: ...

Iterate on the skill body until the output looks right.
