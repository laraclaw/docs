## Introduction

The Bash superpower lets the agent execute arbitrary shell commands on the machine running your Laravel app. There is no sandbox. It's disabled by default.

## Enabling Bash

```env
LARACLAW_BASH_ENABLED=true
```

When disabled, the tool is not registered with the agent at all.

## Command Execution

The tool accepts:

| Parameter | Required | Description |
|---|---|---|
| `command` | Yes | The shell command or script to execute |
| `timeout` | No | Timeout in seconds. Default 30, capped at 120. |
| `working_directory` | No | Directory to run the command from |

It returns a JSON object with `exit_code`, `stdout`, and `stderr`.

## Output Limits

Both stdout and stderr are capped at **100 KB** each. Anything beyond is truncated with a marker. If the command produces no output, the tool returns a `note` field instead.

## Security Considerations

> [!WARNING]
> The Bash tool runs as whichever Unix user the PHP process belongs to. Whatever that user can do, the agent can do.

- **Don't enable this on a shared host** or any machine where the PHP process has access to data the owner shouldn't see.
- **Inbound messages can influence prompts.** Anyone who can message a trusted sender or DM the bot can in principle convince the agent to run a command. Trust your trusted senders.
- **Set `LARACLAW_LOG_AGENT_REQUESTS=true`** to keep an audit trail of every prompt and response.
- **The agent will sometimes execute the wrong command in good faith.** Treat the Bash tool the way you'd treat giving any human contractor shell access.

If you only need the agent to query your application's data, the [Eloquent superpower](/superpowers/eloquent) has a tighter blast radius.
